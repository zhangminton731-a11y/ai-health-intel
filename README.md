# 健微知著 · AI+健康产业情报站

> **从微小的信号，看见产业的大势。**
> 名字取自"见微知著"：为 AI+健康赛道的创业者，把全球公开信息里微弱的早期信号，加工成看得懂、可核验、能指导决策的中文产业情报。

**🌐 在线访问**：https://zhangminton731-a11y.github.io/ai-health-intel/
**状态**：MVP 试运行中（每日北京时间 08:30 自动更新） · 引擎 June SIH（MIT） · 版式参考 AI Hot（MIT） · UI Tailwind CSS（MIT）

## 一、目标与定位

### 为谁做（用户优先级已定死）

1. **AI+健康领域创业者**——第一优先用户，也是本项目要探索的市场与买单方；
2. 医疗健康企业管理者、产品与商务（第二批）；
3. 医务工作者（合作方自有渠道触达，不依赖本站）；
4. AI+健康爱好者（暂不作为目标用户）。

### 解决什么问题

AI+健康赛道信息爆炸但良莠不齐：融资、新品、审批、监管、合作信号分散在英文世界与零散渠道里，创业者要么看不过来、要么看不到。本站把分散信息加工为**可核验、可解释、可追溯**的中文情报——每条都能回答：**从哪来、为什么值得看、可能影响什么、可信度多高**。

### 明确不是什么（第一版禁区）

- ❌ 不是收费系统 / 社区 / 复杂 SaaS（定位：引流入口 + 用户粘性工具，类似 AI Hot 之于"数字生命卡兹克"）
- ❌ 不做付费订阅、评论社区、用户注册、个性化推荐、自动推送、独立 App
- ❌ 不做普通新闻网站：信源质量与筛选逻辑优先于页面效果
- ❌ 不生成医疗建议或功效背书

### 长线愿景（只做设计预留，当前不实现）

**SIH（Scientific Information Hub）**：面向医疗与生命科学从业者、机构与企业的可溯源情报基础设施——两个核心特点：可溯源情报结构 + **Agent 原生**（通过协议让外部 Agent 便于获取与跟踪情报）。当前数据结构（稳定 ID、provenance 溯源、JSONL 事实池）为此预留，不阻断。

## 二、产品形态

### 版块（AI Hot 式信息流导航站）

| 版块 | 内容 |
|---|---|
| 精选 | 今日精选（为什么值得看）+ 热点 TOP 10 |
| 全部情报 | 全量条目，分类 × 层级双维过滤 |
| 热点榜 | 相关度 TOP 30 + 主题热词云 |
| AI 日报 | 精选 + TOP10 摘编，一键复制转发微信群 |
| 来源健康 | 每信源运行状态（连续失败自动告警降级） |
| 关于与方法 | 评分方法、信源四级制、诚实声明 |

### 情报卡要素

中文标题 + 英文原题、信源与等级、发布时间、中文摘要、**相关度分（0–100）**、**信源可信度色点（●●● 高/中/低）**、层级（必读/速览/浏览/归档）、原文链接。规划中：完整五维情报分（相关性 30%/重要性 25%/信源可信 20%/市场影响 15%/时效 10%）、"为什么值得看"与潜在影响的 LLM 增强。

### 信源组合（一主多辅，全部经可用性验证）

| 角色 | 信源 | 通道 |
|---|---|---|
| **主** | MedTech Dive | RSS |
| 辅 | STAT News / Crunchbase News / Rock Health | RSS |
| 观察 | Hacker News（关键词信号） | API |
| 待合并 | 需求方 70+ 信源清单（`SIJ-xxx` 编号接口已预留） | —— |

信源四级制：官方确认 / 权威媒体 / 行业信源 / 待交叉验证（**默认不公开**）。

### 技术架构

```text
公开信源(RSS/API) → SIH 引擎（采集→标准化→去重→时效门→评分分层）
  → JSONL 事实池 + 来源健康
  → build_site.py（gtx 翻译缓存+熔断 → 中文渲染）
  → 静态站 → GitHub Pages
GitHub Actions 每日定时聚合，质量门校验，聚合成功才部署（失败隔离）
```

- **零第三方 Python 依赖**，零 LLM/账号依赖（翻译走免费接口，缓存+熔断降级）
- 三重安全开关：`--live`（联网）/ `--llm`（模型）/ `--publish`（外发），互不隐含
- 原始数据不可变、幂等（item_id + fingerprint）、全链路可追溯（provenance）

## 四、验收标准（V1 demo 裁剪版）

| 指标 | 标准 |
|---|---|
| 更新自动化 | 连续四周每日自动更新；>36h 无成功运行必须触发告警 |
| 信源覆盖 | 5 个已验证信源全部在线（1 主 4 辅） |
| 领域相关率 | 抽样相关率 ≥80%（内部用户标记"相关/不相关"） |
| 去重质量 | 同一事件多来源报道默认合并为一张卡 |
| 情报产出 | 每周 ≥10 张可公开情报卡 + 每日日报 |
| 链路追溯 | 每张卡可回溯到原始条目（provenance）与评分明细 |
| 公开安全 | 未验证/未审核内容不进入公开入口 |
| 人工效率 | 日常维护 ≤20 分钟/天 |

**生产版完整验收**（每 6 小时采集、审核台、两账号权限、恢复演练等）见《产品设计规格 V1.0》第 13 章，V2 起逐步对齐。

## 五、开放问题与模糊区间（诚实清单）

以下事项**尚未定案**，按当前理解推进，等需求方/数据反馈后收敛：

1. **内容边界宽窄**：主题词已收敛为"AI+健康"（宽口径引流），产品设计规格聚焦"运动健康 AI 硬件"（窄口径深度板块）——当前按"宽主题 + 窄深度板块"并行处理，规格 V1.1 待需求方书面确认。
2. **公开门槛**：筛选方案定义"综合分 ≥60 才可公开"，当前页面为透明起见展示全部条目（归档以标题露出）——收口时机待试运行数据决定。
3. **评分维度缺口**：五维中"事件重要性、市场影响"两维尚无实现（词表起步），LLM 抽取效果未验证。
4. **人工审核缺位**：V1 无审核台，页面明示"未经人工审核"；审核流程 V1.5 补齐。
5. **70+ 信源清单**：需求方手上有存量清单未提供，Atlas 已留合并接口，到位后增量并入。
6. **域名与品牌**：当前用 GitHub Pages 默认域名；正式域名待注册绑定；站名「健微知著」已定，仓库/组织名 `ai-health-intel` 是否随品牌调整未定。
7. **模型与账号**：当前零 LLM 依赖；翻译/摘要/分诊的模型选型（DeepSeek/GLM/免费接口）开放，待试运行成本与质量数据。
8. **商业模式**：需求方明确"先引流、不考虑收费"；后续变现路径（社群/合作对接/订阅）不在当前版本设计范围。

## 六、本地运行

```bash
# Python 3.10+，零第三方依赖
git clone https://github.com/zhangminton731-a11y/ai-health-intel
cd ai-health-intel
PYTHONPATH=engine/src python -m sih_ref.cli run \
  --config config/sources.json --profile config/profile.json \
  --output-dir output            # 离线冒烟；加 --live 联网采集
python scripts/build_site.py      # 生成中文站点与日报
python scripts/quality_gate.py    # 质量门
```

Windows 下网络出口需代理时：设置 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量即可（脚本走系统代理）。

## 七、仓库结构

```
engine/        SIH 参考实现（MIT）——采集/标准化/去重/评分/渲染内核
config/        sources.json（信源）+ profile.json（筛选词表与阈值）
scripts/       build_site.py（中文站与日报）/ quality_gate.py
output/        事实池 JSONL、日报（中/英）、来源健康、静态站、增量状态
.github/workflows/  aggregate.yml（每日聚合）+ deploy.yml（Pages，失败隔离）
```
